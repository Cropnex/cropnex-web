What changed:
- The login/register form is rendered in the initial server response instead of being replaced by a browser-only Suspense loading message.
- Login and account creation links on the landing page use normal document navigation.
- Auth SDK loading is deferred until a user requests an action. Login SDK loading and sign-in requests have timeouts.
- The service worker no longer caches or serves offline copies of login/auth pages. Auth responses request no-store caching.
- Settings uses readable dark text on white surfaces for the currency selector, its options, account email, labels and description.

Verification:

- TypeScript checks passed.
- New Settings text contrast ratios checked at 15.94:1 for account/currency text, 9.65:1 for labels, and 6.13:1 for Sign out.
- The current production landing-page Log in link loaded successfully in the available browser. The client's particular Edge failure was not reproduced.
